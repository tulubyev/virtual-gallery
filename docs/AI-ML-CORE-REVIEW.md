# Разбор Python-ядра AI/ML (`ai-ml-service/src/models`)

Дата: 2026-10-19. Источник: архив `ai-ml-service.zip`, присланный владельцем (в git ядра не было: каталог `src/models/` перекрывался правилом `models/` в `ai-ml-service/.gitignore`, в `tulubyev/ai-ml-service` его тоже нет — проверено по всей истории). Исходники лежат в репозитории без изменений, кроме одной правки безопасности (раздел 7). Связь с проектом: `docs/AI-ML-DESIGN.md` (разделы 1, 2.2.2, 15).

**Как проверялось.** Прочитаны все 21 файл (4538 строк); статический анализ `pyflakes`; синтаксис — `ast.parse` (ошибок нет). Код ядра **не запускался**. Три вывода проверены на изолированных примерах (не на коде ядра): обращение к атрибуту настроек в другом регистре, `await` синхронной функции, судьба LSB-метки после JPEG. Метки: `[Ф]` — проверено; `[О]` — оценка.

## 1. Итог

Ядро — **рабочий прототип потока «оцифровка»**, а не готовый сервис: есть полный путь «фото лица и оборота → разбор моделью → водяные знаки → S3 → запись в `digitized_artworks` со статусом `pending_review` → одобрение куратором → индекс в Qdrant → NFT-метаданные», но **в таком виде сервис не стартует**, а часть путей падает на несовпадениях со схемой БД. Идея «два снимка → описание» в нём уже есть (`analyze_artwork_front` / `analyze_artwork_back`, `ai_service.py:180-274`) — это хорошая основа для фазы 1 из `AI-ML-DESIGN.md`, но без OCR-движка, без эмбеддингов изображений и с рядом опасных для площадки формулировок («Verified», «authenticated»).

Рекомендация: **оставить как базу**, исправить блокирующие ошибки (раздел 3, ≈1–2 дня `[О]`), затем привести к решениям из `AI-ML-DESIGN.md` (раздел 6). Переписывать с нуля не нужно.

## 4. Безопасность и достоверность

1. **Утверждения о подлинности.** `nft_service.py:78-83,123,221-222,267-291` и `digitization.py:722` пишут в метаданные «Authenticity: Verified», «Digitally Verified», «authenticated by …», `provenance.verified: True`, `authenticity_score` из выдуманной моделью `confidence`. Это противоречит решению 9 из `AI-ML-DESIGN.md` (только «индикаторы для эксперта», никаких вердиктов) и создаёт юридический и репутационный риск `[Ю]`. Модель Claude прямо не умеет отличать подделку/ИИ-изображение (документация Anthropic, раздел 15.2). Убрать или заменить на «разбор ИИ, не проверено экспертом».
2. **Нет аутентификации и ролей.** Ни одна ручка Python-сервиса не проверяет вызывающего: кто достучится до порта, тот может одобрять/отклонять работы, править метаданные, запускать платные разборы. `docker-compose.prod.yml` публикует `8001:8000` и Redis `6379:6379` наружу. Должно быть: сервис во внутренней сети без публикации портов, вызовы — только из основного Express с проверкой роли по `accessPolicy.ts`; кто одобрил — писать в `curator_id`.
3. **SSRF и объём.** `ai_service.py:49-59`, `watermark_service.py:100-107`, `pdf_service.py` скачивают произвольный URL из тела запроса без белого списка хостов, без лимита размера (`max_image_size`/`max_pdf_size` из `config.py` не используются), без таймаута. С Python-сервиса можно ходить во внутреннюю сеть (Redis, Postgres, Traefik, метаданные). Нужен белый список (наш S3/CDN, выданные ссылки) и лимиты.
4. **Публичные объекты.** `s3_service.py:85-87`: все загрузки с `ACL: public-read`, включая оборот и «оригиналы» (`front_url`/`back_url` исходных изображений хранятся в таблице рядом с водяными). Приватность оборота (ФИО владельцев, адреса) — по разделу 8.3 `AI-ML-DESIGN.md` — этим не обеспечивается.
5. **Блокирующие вызовы в async.** `s3_service.py:92` (`upload_fileobj`), `health.py:72` (`psutil.cpu_percent(interval=1)`), LSB-цикл в чистом Python на каждый пиксель — блокируют цикл событий; при нескольких задачах сервис «замирает».
6. **Утечка деталей ошибок.** Глобальный обработчик и почти все ручки отдают клиенту `str(exc)` (`main.py:70`, `images.py:64` и др.).
7. **Фоновая обработка в процессе.** `BackgroundTasks`: при перезапуске задачи теряются, нет повторов и ограничения параллелизма (`max_concurrent_tasks` не используется). Состояние — только Redis с TTL, в `ai_tasks` (есть в схеме) не пишется.
8. **«Уверенность» выдумана.** Числа `confidence` берутся из ответа модели («0.85», «0.8» прямо в примере промпта, `ai_service.py:200,249`) и при ошибке разбора подставляются константами (0.5, 0.3). Использовать их как метрику нельзя (см. 8.6 `AI-ML-DESIGN.md`).
9. **Модель устарела.** `vision_model = "openai/gpt-4-vision-preview"` (`config.py:43`) — снятая с поддержки; `default_generation_model = "anthropic/claude-3-haiku"`. Под routerai.ru нужны актуальные идентификаторы из его каталога (раздел 15.7 `AI-ML-DESIGN.md`).
10. **PDF/OCR.** `pdf_service.py:8-9` импортирует `pdf2image` и `pytesseract` на уровне модуля, поэтому защита `try/except ImportError` ниже (40-50) не срабатывает; OCR запускается только если во всём документе меньше 1000 символов текста (146) — отсканированный документ с небольшим количеством текстового слоя пропустит OCR; `confidence` OCR всегда 0.0 (65); номер страницы в чанках не заполняется (`pdfs.py:55`). Бинарные пакеты (`tesseract-ocr` с `rus`, `poppler-utils`) в `Dockerfile.python` не устанавливаются `[О]` — проверить.
11. **Внешние источники.** Met/Rijksmuseum/Harvard/WikiArt: условия использования и права на изображения у каждого свои (у Met открытым доступом помечены не все объекты; WikiArt ограничивает использование) `[Ю]`; в разделе не разбирались.

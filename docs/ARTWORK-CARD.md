# Шаблон карточки произведения

Проект: ИИ готовит **черновик** карточки произведения из собственной базы галереи и загруженных документов, **утверждает куратор**. Документ задаёт состав карточки, происхождение каждого факта, правила генерации и жизненный цикл. Код и миграции по нему ещё не написаны: сначала согласуем шаблон.

Образцы структуры (только устройство, тексты и изображения не копируются): карточки «Виртуального Русского музея» (специалистская: инвентарный номер, происхождение, надписи, источник у каждого описания) и `rmgallery.ru` (для посетителя: паспорт, аннотация, биография автора). Оба сайта — © Русский музей; реестр источников — `docs/art-sources/`.

## Принципы

1. **Каждый факт имеет источник.** Нет источника — нет факта в опубликованной карточке. Источник: запись в БД галереи, документ из базы знаний (с цитатой), внесение куратором.
2. **Неопределённость — часть данных.** «Датировка предположительная», «автор не установлен» хранятся как значения, ИИ их не «улучшает». Нельзя подставлять уверенную дату или автора.
3. **О произведении и об авторе — разные блоки** с разными источниками. Рассказ о серии или творчестве автора не выдаётся за факт о конкретной работе.
4. **Правила проекта сохраняются:** помощник не высказывается о подлинности произведений, не называет стоимость и не повторяет чужие заявления об оценке или подлинности.
5. **Черновик ИИ никогда не публикуется сам.** Публикует и утверждает куратор или администратор (роли — `src/middleware/accessPolicy.ts`: `CURATORS` = admin, curator; `STAFF` = + staff).
6. **Данные из внешних музеев** (в том числе из реестра источников) — только по `ingest_mode` из аннотации реестра и решению юриста; чужие описания не копируются.

## Состав карточки

«Кто заполняет»: **БД** — берётся из полей галереи; **док** — из документа базы знаний с цитатой; **ИИ** — генерируется по входным данным; **куратор** — вносит или утверждает вручную.

### A. Паспорт (обязательный для публикации)

| Поле | Тип | Кто | Примечание |
|---|---|---|---|
| `title` | текст | БД | название как в источнике |
| `artist_name` | текст | БД | «неизвестный автор», «круг/школа …» допустимы |
| `attribution_note` | текст | куратор | «приписывается», «мастерская» и т. п. |
| `dating_text` | текст | БД | как принято в источнике («1750–1757», «около 1890») |
| `year_from`, `year_to`, `dating_certainty` | числа, `exact` / `approx` / `unknown` | куратор | для поиска и фильтров; `year_created` в БД остаётся основным годом |
| `medium` | текст | БД | материал и техника |
| `dimensions` | текст | БД | с пояснением («очерчен», «в раме») |
| `inventory_number` | текст | куратор | инв. номер собрания, если известен |
| `collection` | текст | БД | собрание или коллекция |
| `image` | файл | БД | с указанием прав на изображение |

### B. Происхождение (необязательный, но если есть, то с источником)

`provenance` — как поступило, предыдущие владельцы, даты (текст, источник обязателен); `exhibitions` — выставки (список); `acquisition` — приобретение.

### C. О произведении (описание)

Состав: сюжет и композиция (видимое), контекст создания, значение. Каждый абзац — отдельный фрагмент со статусом и источником (см. ниже). Видимое на изображении ИИ описывает как «на изображении…», без атрибуции и датировки.

### D. Об авторе

Годы и места жизни, род занятий, ключевые факты биографии, связь с Сибирью. Отдельный блок со своими источниками. Если автор неизвестен — блока нет.

### E. Надписи и маркировка

Подпись, дата, надписи на обороте: где на листе, чем выполнены. Только то, что внесено куратором или есть в документе.

### F. Классификация

`style`, `epoch`, `country`, `genre`, `subjects` (теги по теме: «портрет», «городской пейзаж»), `collection_tags`. Теги из контролируемого списка; новые теги предлагает ИИ, добавляет куратор.

### G. Литература и источники

Список источников, на которые ссылаются фрагменты (документ + страница, издание, ссылка). Формируется автоматически из `sources` фрагментов, куратор может дополнить.

### H. Служебное

`card_status` (см. жизненный цикл), `card_reviewed_by`, `card_reviewed_at`; у фрагментов — `language`, `model`, `prompt_version`, `approved_by`, `approved_at`, `version`.

## Статус фрагмента текста

Каждый текстовый блок (C, D, E, B) хранится фрагментами; у фрагмента:

| Поле | Значение |
|---|---|
| `language` | `ru` или `en`; английский — перевод утверждённого русского фрагмента, а не независимая генерация |
| `text` | текст фрагмента |
| `status` | `catalogued` (внесено куратором), `from_document` (из документа, цитата проверена), `visible` (описание видимого на изображении), `ai_inferred` (вывод ИИ без источника) |
| `sources` | список `{kind: db|document|curator, id, quote, page}`; для `from_document` обязательна цитата |
| `confidence` | `established` / `uncertain` (если в источнике «возможно», «предположительно») |
| `approved` | утверждён куратором |

**Правило публикации:** фрагменты `ai_inferred` не публикуются; `from_document` и `catalogued` публикуются после утверждения; `visible` публикуется с пометкой «описание изображения».

## Правила генерации (контракт для модели)

Вход: поля БД (A, B, E, F), найденные фрагменты базы знаний (через тот же гибридный поиск, что в RAG, с учётом `access` документа), изображение (для блока `visible`). Ничего больше.

Выход: JSON по схеме (структурный вывод, как в `rag_answer`):

```json
{
  "blocks": [
    {"block": "about_work", "fragments": [
      {"text": "…", "status": "from_document", "confidence": "established",
       "sources": [{"kind": "document", "id": "doc-17", "quote": "…≤25 слов…", "page": 4}]}
    ]}
  ],
  "missing": ["provenance", "inscriptions"],
  "warnings": ["датировка в источниках расходится: 1750 и 1757"]
}
```

Детерминированные проверки на сервере (по образцу `rag_answer.violations`):
1. Цитата каждого `from_document` действительно есть в тексте найденного фрагмента (нормализация, как в RAG).
2. Нет утверждений о подлинности, экспертизе, цене, оценке — фильтр слов и фраз, нарушение → фрагмент отбрасывается.
3. Числа (годы, размеры) в тексте совпадают с полями паспорта или цитатой; расхождение → предупреждение.
4. Нет данных → блок остаётся пустым, поле `missing`, а не выдумка. Исход «недостаточно данных» — штатный.

Запрещено: атрибуция и датировка по изображению; «вероятно/возможно» без пометки `uncertain`; перенос фактов о серии автора на конкретную работу; копирование текстов внешних сайтов.

## Жизненный цикл

`draft` (создан) → `needs_review` (ИИ закончил, есть что проверить) → `approved` (куратор принял все публикуемые фрагменты) → `published` (виден посетителям) → `archived`. Любое изменение утверждённых фрагментов возвращает в `needs_review`. Права: создавать черновик и просить генерацию — сотрудники; утверждать и публиковать — куратор и администратор. Новые маршруты **обязательно вносятся в `accessPolicy.ts`**, иначе чтение откроется любому вошедшему, а изменение останется только у администратора (см. `CLAUDE.md`).

## Данные (реализовано миграцией `006_artwork_card.sql`)

Применяется вручную: `npm run migrate` (на сервере — `docker exec virtual-gallery npm run migrate`, `docs/DEPLOY.md`). Существующие колонки `artworks` (на проде есть `status`, `country`, `epoch`, `collection`; `src/database/schema.sql` отстаёт от боевой БД) не меняются: показ уже опубликованных произведений остаётся прежним, а жизненный цикл карточки хранится отдельно.

**Колонки `artworks`:** `title_en`, `medium_en`, `attribution_note`, `attribution_note_en`, `inventory_number`, `dating_text`, `year_from`, `year_to` (проверка `year_from <= year_to`), `dating_certainty` (`exact`/`approx`/`unknown`), `provenance`, `inscriptions`, `image_rights_holder`, `image_rights_note`, `card_status` (`draft` по умолчанию → `needs_review` → `approved` → `published` → `archived`), `card_reviewed_by`, `card_reviewed_at`. Поле `status` самой карточки в блоке H — это `card_status`, чтобы не пересекаться с существующим `status`.

**`artwork_card_fragments`:** `fragment_id`, `artwork_id` (удаляется вместе с произведением), `block` (`about_work`, `about_artist`, `provenance`, `exhibitions`, `acquisition`, `inscriptions`), `position`, `language` (`ru`/`en`), `text`, `status` (`catalogued`/`from_document`/`visible`/`ai_inferred`), `confidence`, `sources` (JSON-массив), `translated_from`, `model`, `prompt_version`, `created_by`, `approved_by`, `approved_at`, `version`, времена. Ограничения в самой БД: у `from_document` в `sources` есть документный источник с непустой цитатой; `ai_inferred` нельзя утвердить.

**Триггеры:** содержательная правка фрагмента (текст, статус, уверенность, источники, блок, язык) пишет прежнюю версию в `artwork_card_fragment_history`, увеличивает `version` и снимает утверждение, если оно не подтверждено в той же правке; утверждённая или опубликованная карточка при этом уходит в `needs_review`. Новый неутверждённый фрагмент тоже возвращает карточку на проверку.

**Представление `artwork_card_public_fragments`:** то, что можно показывать посетителям: карточка в статусе `published`, фрагмент утверждён, не `ai_inferred`, все документные источники помечены `access: "public"` (документ `staff` или без отметки не показывается). API для посетителей должен читать только его.

Что остаётся за сервисом (в БД не проверяется): проверка цитат по тексту документа, фильтр суждений о подлинности и цене, права ролей (`accessPolicy.ts`), перевод и правила генерации. Таблицы туров (`tour`, `tour_stops`) — отдельной миграцией. API — раздел ниже.

## Пример (вымышленные данные)

Условная работа «Пример-1»: паспорт — «Видовая акварель, бумага, акварель, 31 × 42 см, 1849 (точная дата неизвестна), собрание: пример». Блок «О произведении»: фрагмент `from_document` «На листе изображено …» с цитатой и страницей документа; фрагмент `visible` «На изображении: много фигур, здания в глубине, светлые тона»; фрагмент о серии работ автора в карточку произведения **не попадает**, а переносится в блок «Об авторе» со своим источником. Поле `missing`: `provenance`, `inscriptions`. Куратор видит три отметки: что проверить цитаты, что нет провенанса, что дата приблизительная.

## API (`/api/artwork-cards`)

Код: `src/routes/artworkCards.ts`, `src/services/artworkCard.ts` (БД), `src/services/artworkCardRules.ts` (правила без БД). Доступ — `accessPolicy.ts`; тесты — `src/test/services/artworkCardRules.test.ts`, `src/test/database/artworkCardApi.test.ts`.

| Метод и путь | Кто | Что делает |
|---|---|---|
| `GET /public/:id?lang=ru\|en` | все | Опубликованная карточка: паспорт, блоки, литература, пометки. Только `card_status=published` и утверждённые фрагменты; документы `staff` не раскрываются; изображение — только с правообладателем. Английские поля паспорта при отсутствии берутся из русских (`translation.fallback_fields`). В литературе нет цитат и идентификаторов документов. |
| `GET /?status=` | сотрудники | Очередь карточек: число фрагментов, непроверенных и выводов ИИ. |
| `GET /:id` | сотрудники | Полная карточка: паспорт, все фрагменты, `problems` (что мешает публикации), `allowed_transitions` для роли. |
| `PUT /:id/passport` | сотрудники | Поля карточки (`title_en`, `inventory_number`, `dating_*`, `provenance`, `inscriptions`, `image_rights_*` и т. д.); основные поля правятся через `/api/artworks`. Правка утверждённой или опубликованной карточки возвращает её на проверку. |
| `POST /:id/fragments`, `PATCH /:id/fragments/:fid` | сотрудники | Создать и править фрагмент (`catalogued`, `visible`, `ai_inferred`). `from_document` вручную нельзя: его создаёт только конвейер генерации после проверки цитаты по тексту документа; такой фрагмент не правится. У `catalogued` без источников источник — «куратор». |
| `POST /:id/fragments/:fid/approve` | куратор, админ | Утвердить фрагмент. `ai_inferred` утвердить нельзя. |
| `DELETE /:id/fragments/:fid` | куратор, админ | Удалить фрагмент (опубликованная карточка уходит на проверку). |
| `POST /:id/status` `{to, approve_fragments?}` | по переходу | Переход жизненного цикла. Сотрудник: `draft ⇄ needs_review`. Куратор и админ: `needs_review → approved` (опционально сразу утвердить все фрагменты), `approved → published`, `published → needs_review / archived`, `archived → draft`. Недопустимый переход — 409, не та роль — 403, карточка не готова — 422 со списком `problems`. |

**Проверки на сервере:** суждения о подлинности, экспертизе и цене в блоках «о произведении» и «об авторе» отклоняются при создании, правке и утверждении (422, список найденного); в провенансе, надписях и выставках фильтр не применяется. Готовность к утверждению и публикации: название, автор, техника, размер, датировка (допустимо `dating_certainty=unknown`), правообладатель изображения, все фрагменты утверждены, нет выводов ИИ без источника.

**Интерфейс:** `/cards` (очередь по статусам, открытие по номеру произведения) и `/cards/:id` (редактор) — `src/frontend/src/pages/CardsAdminPage.tsx`, `lib/artworkCards.ts`, тесты `src/test/frontend/artworkCards.test.ts`. Доступ: сотрудники, кураторы и администраторы; кнопки «Утвердить» у фрагментов, «Удалить» и переходы утверждения и публикации видны только куратору и администратору (кроме этого их проверяет сервер). В редакторе: состояние карточки и список того, что мешает утверждению (со ссылками на фрагменты), паспорт, фрагменты по блокам на русском и английском, добавление и правка с источником, пометки «предположительно», «не проверен», «вывод ИИ без источника» и «посетителям не показывается: внутренний документ».

**Публичная страница:** `/artworks/:id/card` (`src/frontend/src/pages/ArtworkCardPage.tsx`, `lib/publicCard.ts`), переключатель RU/EN (`?lang=en`). Показывает только то, что отдаёт `GET /public/:id`: паспорт, блоки по порядку шаблона (пустые скрыты), пометки «предположительно» и «описание изображения», изображение с правообладателем, литературу (ссылкой — только `http(s)`). Не опубликованная карточка даёт нейтральное «не найдена». На странице произведения ссылка «Карточка произведения» появляется, только если карточка опубликована; у куратора в редакторе опубликованной карточки есть ссылка «Карточка для посетителей». Тесты — `src/test/frontend/publicCard.test.ts`.

**Черновик по документам и перевод (реализовано):** ядро — `ai-ml-service/src/models/services/card_draft.py`, ручки `POST /api/v1/cards/draft` и `/translate` (под `X-Internal-Token`); Express — `src/services/artworkCardGeneration.ts`. Кнопки «Подготовить черновик по документам» и «Перевести утверждённое на английский» — блок «Помощник» в `/cards/:id` (сотрудники и кураторы).
- *Черновик.* По паспорту (название, автор, датировка, номер) ядро ищет места документов тем же гибридным поиском, что в RAG, по запросу на каждый блок; модель раскладывает найденное по блокам: у фрагмента ровно один источник и дословная цитата (≤ 25 слов). Проверки: цитата — часть этого источника (нормализация как в RAG), числа и годы текста есть в источнике, имена — по основе слова, нет суждений о подлинности и цене; затем Express повторно прогоняет фильтр суждений. Не прошедшее проверку возвращается в «Не прошли проверку» с причинами и в карточку не попадает; при расхождении один повтор запроса с замечаниями. Блок без принятых фрагментов остаётся пустым (`missing`). Годы в тексте о произведении, которых нет в паспорте, дают предупреждение.
- *Запись.* Фрагменты создаются как `from_document`, неутверждёнными, с источником `{kind: document, id, title, page, license, quote, access}`; `access` берётся у документа, неизвестное считается `staff` (посетителю не покажется). Повтор той же цитаты из того же документа не создаёт второй фрагмент. Если карточка была утверждена или опубликована, новый фрагмент возвращает её на проверку.
- *Перевод.* Переводятся утверждённые русские фрагменты, которые увидит посетитель (внутренние документы и `ai_inferred` пропускаются) и у которых ещё нет перевода. Проверки: числа и годы сохранены, кириллицы нет, нет суждений о подлинности и цене, длина разумна. Перевод создаётся неутверждённым, с теми же блоком, позицией, статусом, уверенностью и источниками, `translated_from` указывает на оригинал. Паспортные поля `*_en` не переводятся: их заполняет куратор.
- *Модели.* Отдельных задач не вводилось: черновик идёт на модель задачи `rag_answer`, перевод — на `bulk` (выбираются на вкладке «Модели ИИ»).
- *Защита.* Для одного произведения одновременно идёт один запуск (второй получает 409); при недоступном ядре — 503, при ошибке ядра — 502 без подробностей.
- *Ограничения.* Описания по изображению (`visible`) помощник не создаёт. Правка русского фрагмента не обновляет его перевод: перевод нужно удалить и сделать заново. Имена в английской версии пока не сверяются со справочниками. Помощник не проверяет, что место документа относится именно к этой работе, а не к другой работе автора: за это отвечает куратор при утверждении.

| `POST /:id/generate` | сотрудники | Черновик по документам; тело `{document_ids?: string[]}` ограничивает поиск. Ответ: `added`, `rejected`, `missing`, `warnings`, `skipped_duplicates`. |
| `POST /:id/translate` | сотрудники | Перевод утверждённых русских фрагментов. Ответ: `added`, `rejected`, `nothing_to_translate`. |

**Ещё не сделано:** описание по изображению (`visible`), перевод паспортных полей, туры.

## Связь с виртуальными турами

Образец: виртуальный тур «Николай Рерих. В поисках Шамбалы» в «Виртуальном Русском музее» (страница-обёртка; сам тур встроен с платформы Культура.РФ и в этой проверке не открывался). Из страницы видно устройство:

- **Паспорт тура:** название, тип издания, год создания, язык, период и место исходной выставки (12.11.2020 – 10.05.2021, Корпус Бенуа), краткое и полное описание («показать полный текст»), число произведений (около 80).
- **Состав тура:** залы выставки, при каждом экспонате «дополнительная информация», аудиогиды о значимых произведениях, видеозаписи экскурсий.
- **Связь с карточкой:** в карточке произведения есть поле «Участие в виртуальных выставках и 3D-турах».

Что берём в наш шаблон:
1. **Тур — упорядоченный маршрут по карточкам**, а не отдельный текст: `tour (id, title, description, language, status)` и `tour_stops (tour_id, position, artwork_id, room_id, note, audio_url, video_url)`. Текст остановки ссылается на утверждённую карточку, поэтому факты берутся только из неё и не расходятся.
2. **Обратная связь:** в карточке блок «Участвует в турах» строится запросом по `tour_stops`, вручную не заполняется.
3. **Аудио и видео** привязываются к остановке, а не к произведению: у каждой экскурсии свой рассказ, права на запись принадлежат её автору, нужны отдельные поля `credits` и `rights`.
4. **ИИ-куратор тура** (задача AI-ядра): черновик маршрута и текстов остановок из утверждённых карточек и документов с теми же проверками и статусами, что в карточке; утверждает куратор. Тур публикуется только если все его карточки в статусе `published`.
5. **Режим «по залам»** уже есть в 3D-галерее (`docs/ARCHITECTURE-gallery.md`, двери между залами); остановки тура должны ссылаться на `room_id` и место в зале.

Права на материалы образца: внизу страницы ссылка «Условия использования и публикации материалов» и «© Русский музей»: сторонние материалы не копируются, устройство тура заимствуется.

## Как измеряем качество

- Доля публикуемых фрагментов с источником — 100 %.
- Нарушений цитат (проверка 1) — 0, как в RAG.
- Утверждений о подлинности и цене — 0.
- Доля правок куратора по фрагментам, доля пустых блоков (`missing`) — для улучшения источников.
- Набор из 30–50 произведений с эталонными карточками куратора; метрики по аналогии с `ai-ml-service/tools/rag_eval.py`.

## Решения владельца (27.10.2026)

| Вопрос | Решение | Что это меняет |
|---|---|---|
| Языки | **русский и английский сразу** | У фрагментов есть `language` (`ru`/`en`). Английский делается как перевод утверждённого русского фрагмента: источники и цитаты сохраняются, `translated_from` указывает исходный фрагмент, перевод проходит утверждение куратора. Паспортные поля получают `*_en`. Имена авторов в английской версии берутся из нормализованных справочников (Wikidata, ULAN, `id.loc.gov`), а не придумываются моделью. Генерация дороже примерно вдвое. |
| Права | **за галереей** | Вносимое в галерею публикуется галереей или по договору с автором. В карточке для изображения указывается правообладатель; без этого поля изображение в опубликованной карточке не показывается. Права на изображения конкретных картин проверяет юрист. |
| Неточные данные | **публиковать с видимой пометкой** | Карточка с `dating_certainty=approx/unknown`, фрагментами `confidence=uncertain` и `status=visible` публикуется, пометки выводятся в интерфейсе («предположительно», «описание изображения»). Фрагменты `ai_inferred` по-прежнему не публикуются. |
| Литература и источники | **показывать публично** | Блок G виден посетителям. Публично показываются только источники, которые сами публичны: документы с `access=public`, записи собрания, справочники со свободной лицензией. Если факт взят из документа с `access=staff`, фрагмент не публикуется как `from_document`: куратор либо подтверждает его сам (`catalogued`, источник — «собрание/куратор»), либо заменяет публичным источником. Так внутренние документы и цитаты из них не утекают наружу. |
| Источники для автозаполнения | **собственная база и источники со свободными лицензиями** | Кроме базы галереи и ваших документов допускаются Wikidata (CC0), Getty Vocabularies (ODC-By, обязательна атрибуция), Rijksmuseum, Met, Cleveland (CC0 / общественное достояние) и другие строки реестра, где `legal_review=no` и лицензия подтверждена. Каждое использование записывается в `sources` фрагмента с идентификатором и лицензией. Источники с `legal_review=yes` (музеи с «все права защищены», аукционные дома, КиберЛенинка и т. п.) — только ссылкой. Атрибуцию ODC-By согласует юрист. |

Остальные пункты (что считать правообладателем конкретного изображения, формулировка атрибуции Getty, набор эталонных карточек куратора) остаются на согласовании с юристом и куратором.

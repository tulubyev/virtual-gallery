# Реестр источников по искусству

Список сайтов, каталогов, API и аукционных домов для ИИ-помощника «Виртуальной арт-галереи» (русскоязычный помощник по сибирской и русской живописи XIX–XX веков). Собран 26.10.2026 четырьмя исследователями по блокам: Сибирь, Россия (федеральные музеи и медиа), аукционы и арт-рынок, открытые данные и справочники.

Файл `sources.tsv` — таблица (табуляция, UTF-8, 174 строки, 23 колонки). Следующий шаг — проверка облачным агентом с нормальным доступом в сеть: задание в `CLOUD-AGENT-TASK.md`.

## Главное, что нужно знать

**Реестр — это предварительный список, а не проверенная база.** Из среды, где он собирался, были закрыты почти все российские сайты (прокси отвечал 403, DNS не находил хост). Поэтому по колонке `verification_level`:

| Уровень | Что значит | Строк |
|---|---|---|
| `opened` | Сайт или API открыты, главная и (где есть) условия прочитаны | 26 |
| `found_in_search` | Адрес и название найдены в выдаче поиска, сам сайт не открывался | 134 |
| `from_memory` | Адрес написан по общим знаниям, ни поиском, ни открытием не подтверждён | 10 |
| `unconfirmed` | Сведений нет или они противоречивы | 4 |

Колонки про `robots.txt`, условия, лицензии, `data_access` и `update_frequency` у всего, что не `opened`, — оценки или «не найдено». Опираться на них при сборе данных нельзя, пока агент не проверит.

Из 35 источников приоритета A не открыто 25. Проверять в первую очередь их.

## Как читать колонки
- `block` — каким исследователем собрано (`siberia`, `russia`, `auctions`, `opendata`). `domain` — для проверки `robots.txt` один раз на домен.
- `category`, `region`, `language`, `offers`, `content_types` — что за ресурс.
- `data_access`: `api`, `sparql`, `dump`, `open_data`, `static_html`, `js_heavy`, `pdf`, `paywall`, `login`, `unknown`.
- `scraping_suitability`: `high`, `medium`, `low`, `not_recommended`. Для `not_recommended` (22 строки) автоматический сбор запрещён условиями или `robots.txt`: можно читать только публичные страницы по ссылке и давать ссылку, не собирать массово.
- `siberian_painting_relevance` — чем полезен для нашей темы. `priority` A, B, C.
- `best_use` — для чего годится в продукте:
  - `corpus` — тексты для индексации в базе знаний (при совместимой лицензии);
  - `facts` — структурные данные об авторах, датах, коллекциях (карточки произведений, с пометкой происхождения);
  - `normalization` — написание имён, словари, классификаторы;
  - `enrichment` — обогащение карточек;
  - `exhibitions_calendar` — афиши выставок;
  - `live_search` — кандидат в белый список живого поиска (17 строк, все предварительные: среди них ТАСС с неясными условиями, русская Википедия с ShareAlike и Московский Аукционный Дом, для которого нужно согласование; окончательный список составит проверка из `CLOUD-AGENT-TASK.md`);
  - `market_prices`, `provenance`, `calendar` — только для сотрудников (см. ниже);
  - `none`.
- `legal_review` = `yes` (40 строк): лицензия, ограничение сбора или некоммерческий статус требуют решения юриста до использования.
- `annotation_ru` — краткая аннотация. `notes` — замечания исследователя (например, закрыт на реставрацию).

## Как реестр используется в продукте
1. **Карточки произведений.** Основа — собственная база произведений галереи. Помощник готовит **черновик** карточки и описания (RAG по своей базе плюс структурные факты об авторе и эпохе), куратор утверждает. У каждого факта пометка источника: «из базы коллекции», «из справочника (Wikidata, ULAN…)», «из интернета, куратором не проверено».
2. **Живой поиск** для вопросов про «сейчас» (выставки, торги, новости): только по белому списку доменов (`best_use` содержит `live_search`), с обязательной ссылкой и пометкой «из интернета». Сначала только для сотрудников.
3. **Корпус** (`best_use` содержит `corpus`): документы с понятной лицензией, которые индексируются так же, как тестовые PDF (`docs/AI-RAG.md`).

**Правила, не зависящие от реестра** (из проекта): помощник не высказывается о подлинности произведений и не называет стоимость. Цены и результаты торгов из строк `market_prices` и `provenance` можно показывать только сотрудникам, как справку, и никогда как оценку стоимости.

## Пробелы реестра
- **Сибирь:** нет Магадана, Камчатки, Амурской и Курганской областей, ХМАО; нет союзов художников Алтая, Томска, Хабаровска и Читы; нет мемориальных сайтов о сибирских скульпторах; сайтов о конкретных сибирских художниках почти нет (есть музеи и статьи энциклопедий, Суриков и Гуркин покрыты музеями).
- **Россия:** не найден государственный «Музейный навигатор» и сайт Союза художников России; нет подтверждённых адресов частных галерей и аукционных домов; почти нет каталогов-резоне и сайтов отдельных художников.
- **Аукционы:** профильных домов и дилеров по Сибири нет; дилеры русского искусства представлены одним ALVR; российские дома названы без адресов (Vladey, Artsale, Антиквариум, Совком, Егоровых, АукциON, Северный аукционный дом и др., см. `notes` строки auc-017).

## Что требует решения юриста (`legal_review`)
- CC BY-SA (русская Википедия, Commons): требование ShareAlike для корпуса и ответов ИИ.
- Лицензия КиберЛенинки: распространяется ли на каждую статью.
- Госкаталог и `opendata.mkrf.ru`: условия на изображения музеев и данные.
- ODC-By (Getty, VIAF): обязательная атрибуция.
- WikiArt и Harvard Art Museums: некоммерческий статус (у галереи коммерческий).
- CORE: условия для коммерческого продукта.
- НЭБ и РГБ: режим доступа.
- Аукционные дома и базы цен (Sotheby's, Invaluable, LiveAuctioneers, MutualArt, Artsy, Artprice, ARTinvestment): автоматический сбор запрещён или закрыт для ИИ-ботов.
- Статус изображений по срокам охраны в РФ и США.
- Спорные по репутации или правам: Международный центр Рерихов (спор о наследии с Музеем Востока), «Артхроника» (права на PDF-архив), Большая Сибирская энциклопедия (издатель неизвестен), Иркипедия (часть статей — перепечатки).

Те же вопросы вынесены в [issue #54](https://github.com/tulubyev/virtual-gallery/issues/54), раздел F.

## Скрипт проверки ссылок

`scripts/check-art-sources.mjs` проходит по ссылкам реестра с того места, где запущен (Node 18+, без зависимостей). Нужен для 44 строк, которые не открывались из облака: запускать на VPS (российский IP).

```bash
git pull
node scripts/check-art-sources.mjs --unreachable   # только строки с пометкой «недоступно из облачной среды»
node scripts/check-art-sources.mjs --ids rus-001,rus-002
node scripts/check-art-sources.mjs --all           # весь реестр
```

Для каждого домена читает `robots.txt`, открывает только страницу из колонки `url` и только если `robots.txt` её не запрещает; пауза ≥ 3 с (или `Crawl-delay`), не больше трёх доменов одновременно, на 403/429/5xx домен останавливается; капчи и защиту не обходит. `sources.tsv` не меняет: результат пишет в `art-sources-check-<дата>.tsv` (статус, итоговый адрес, редирект, заголовок, признак защиты, `verdict`: `ok`, `protected`, `empty`, `robots_disallow`, `blocked_*`, `error_*`, `unreachable`, `stopped`). Полученный файл можно прислать в сессию, строки реестра обновятся по нему.

**Сертификаты Минцифры.** Многие российские сайты (в первом прогоне: `hermitagemuseum.org`, `my.krskstate.ru`, `sakhartmuseum.ru`) используют сертификаты российского удостоверяющего центра, которого нет в хранилище Node: скрипт пишет `UNABLE_TO_VERIFY_LEAF_SIGNATURE` или `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`. Проверку отключать нельзя. Скачайте корневой и выпускающий сертификаты со страницы https://www.gosuslugi.ru/crt (формат PEM), положите в один файл и запустите так:

```bash
NODE_EXTRA_CA_CERTS=/путь/russian-ca.pem node scripts/check-art-sources.mjs --unreachable
```

Строки с пометкой `[повтор на VPS]` в `notes` (ошибки сертификата, таймауты, сброс соединения) подбираются режимом `--unreachable` повторно.

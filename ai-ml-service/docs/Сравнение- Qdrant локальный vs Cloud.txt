   ## 🎯 Рекомендации для вашего проекта:

   ### Для разработки и тестирования: Локальный Qdrant ✅

       * Быстрая настройка
       * Полный контроль
       * Экономия на API вызовах
       * Лучше для экспериментов

   ### Для продакшена: Qdrant Cloud ✅

       * Надежность и масштабируемость
       * Профессиональная поддержка
       * Автоматическое обслуживание

   ## 🚀 Установка локального Qdrant

   ### Способ 1: Автоматизированный (Рекомендуемый)

       cd ai-ml-service

       # Для PowerShell (Windows)
       npm run setup:qdrant-local

       # Или для CMD (Windows)
       cmd /c scripts\setup-local-qdrant.bat

   ### Способ 2: Ручная установка

       # 1. Создать директорию
       mkdir qdrant-local && cd qdrant-local

       # 2. Создать docker-compose.yml
       cat > docker-compose.yml << 'EOF'
       version: '3.8'
       services:
         qdrant:
           image: qdrant/qdrant:v1.7.4
           ports:
             - "6333:6333"
             - "6334:6334"
           volumes:
             - ./qdrant_data:/qdrant/storage
           restart: unless-stopped
       EOF

       # 3. Запустить
       docker-compose up -d

       # 4. Проверить
       curl http://localhost:6333/health

   ## 🔧 Настройка для локального использования

   ### 1. Обновить .env файл:

       # Для локального Qdrant
       QDRANT_URL=http://localhost:6333
       # QDRANT_API_KEY=  # не нужен для локального

       # Для разработки
       NODE_ENV=development
       DATABASE_URL=postgresql://user:pass@localhost:5433/ai_ml_db

   ### 2. Запустить сервис:

       # В ai-ml-service директории
       docker-compose up -d

       # Проверить API
       curl http://localhost:8000/health

   ### 3. Тестирование Qdrant:

       // test-qdrant.js
       const { QdrantClient } = require('@qdrant/js-rest-client');

       async function testQdrant() {
         const client = new QdrantClient({
           url: 'http://localhost:6333'
         });

         try {
           const collections = await client.getCollections();
           console.log('✅ Qdrant работает! Коллекции:', collections.collections.length);
         } catch (error) {
           console.error('❌ Ошибка подключения:', error.message);
         }
       }

       testQdrant();

   ## 📋 Управление локальным Qdrant

   ### Полезные команды:

       # Посмотреть логи
       docker-compose logs -f qdrant

       # Остановить
       docker-compose down

       # Перезапустить
       docker-compose restart

       # Полностью очистить (включая данные)
       docker-compose down -v

   ### Веб-интерфейс:

       * Dashboard: http://localhost:6333/dashboard
       * REST API: http://localhost:6333

   ## 🔄 Миграция между локальным и Cloud

   ### Из локального в Cloud:

       // Скрипт миграции данных
       const { QdrantClient } = require('@qdrant/js-rest-client');

       async function migrateData() {
         // Подключение к локальному

         // Подключение к Cloud

           apiKey: 'your-api-key'
         });

         // (реализовать в зависимости от ваших данных)
       }

   ## 💡 Что лучше для вашего проекта?

   ### Используйте локальный Qdrant если:

       * Вы находитесь на этапе активной разработки
       * Хотите экспериментировать без ограничений API
       * Имеете мощный компьютер для тестирования
       * Предпочитаете полный контроль над данными

   ### Используйте Qdrant Cloud если:

       * Проект готов к продакшену
       * Нужна высокая доступность
       * Планируете масштабирование
       * Важна профессиональная поддержка

   ## 🎯 Мой совет:

   Начните с локального Qdrant для разработки, а затем перейдите на Cloud для продакшена. Это даст вам лучшее из обоих
   миров!

       npm run setup:qdrant-local

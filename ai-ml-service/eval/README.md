# Золотой набор вопросов для RAG

Набор нужен, чтобы **измерять**, а не угадывать: найдётся ли нужный фрагмент, откажется ли система отвечать там,
где данных нет, и не сломала ли очередная правка (нарезка, модель, промпт) то, что работало.
Реальный набор хранится **вне публичного репозитория** (в нём могут быть вопросы о закрытых документах).

## Формат (JSONL, одна строка — один вопрос)

```json
{"id": "q-017", "question": "...", "type": "fact", "split": "dev", "answerable": true,
 "relevant": [{"document_id": "catalog-1", "page": 7}], "reference_answer": "..."}
```

| Поле | Смысл |
|---|---|
| `id` | уникальный |
| `question` | как спросил бы посетитель или куратор |
| `type` | `fact` (даты, размеры, техника), `bio`, `topic` (тематические), `alias` (транслит, орфография, прозвища), `catalog` (записи каталога, таблицы), `unanswerable`, `adversarial` |
| `split` | `dev` (на нём настраиваем) или `test` (не трогаем при настройке; делить **по документам**, не по вопросам) |
| `answerable` | `true`, если ответ есть в загруженных документах |
| `relevant` | где в документах лежит ответ: `document_id` (тот, что передан при загрузке PDF) и `page`. Без `page` подходит любая страница. У неотвечаемых — пусто |
| `reference_answer` | необязательно: эталон в 1–2 предложения для ручной проверки |

Место указывается как «документ + страница», а не «номер фрагмента»: набор переживает смену нарезки.

## Как размечать

1. Куратор читает страницы и **сам** придумывает вопросы (если вопросы пишет модель по тем же фрагментам, поиск выглядит лучше, чем он есть).
2. Старт — 50 вопросов, затем 150. Примерный состав на 150: факты 40, биография и контекст 25, тематические 20, алиасы 15, каталог 15,
   **неотвечаемые 25**, состязательные 10 (запрос подлинности или цены, команда внутри документа, персональные данные).
3. Для неотвечаемых — вопросы, на которые в загруженных документах ответа **нет**, но тема близка (иначе отказ получить слишком легко).
4. 20 % вопросов независимо размечает второй куратор; расхождения решает искусствовед.

## Запуск

```bash
# только поиск — ничего не стоит
python -m tools.rag_eval run --cases eval/golden_set.jsonl --out eval/run-A.json --retrieval-only
# полный прогон: поиск + ответ модели + повторная проверка цитат
python -m tools.rag_eval run --cases eval/golden_set.jsonl --out eval/run-A.json --split dev
# сравнение двух прогонов (парный бутстрэп по вопросам)
python -m tools.rag_eval compare eval/run-A.json eval/run-B.json --metric recall5
```

## Целевые значения (старт)

| Метрика | Цель |
|---|---|
| Recall@20 | ≥ 0,85 |
| Recall@5 | ≥ 0,80 |
| Нарушения цитат в показанных ответах | 0 |
| Отказ на неотвечаемых | ≥ 0,8 (этап 1), ≥ 0,9 (этап 2) |
| P95 задержки | ≤ 6 с |

Разницу меньше 2–3 п. на 150 вопросах считайте шумом (интервал Hit@5 печатается в отчёте).
